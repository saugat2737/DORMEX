## 1. Executive Summary

A comprehensive, evidence-based code and architecture audit was performed across all 20 institutional modules of **DORMEX**.

- **Batch-Wise Admission Priority Bug:** **CONFIRMED & FIXED**. The admission priority constraint was previously globally unique across all admissions (`uq_admissions_official_priority`), causing attempts to admit students with priority #1 in 2027 to be rejected if priority #1 existed in 2026. This has been updated to `UNIQUE (academic_year_code, official_priority)` in PostgreSQL DDL and migration scripts, and `student_profiles` now tracks canonical `admission_batch_year` with unique composite index `(admission_batch_year, academic_year, quota_category, assigned_priority)`. All validation services and UI components now enforce and display batch-wise uniqueness.
- **Automated Verification:** 79/79 automated tests passing across 10 test suites (increased from 77 baseline tests). TypeScript check (`tsc --noEmit`) passes with 0 errors. Client production build (`vite build`) completes cleanly.

## 3. Analysis of Suspected Defects & Hypotheses

| Hypothesis from Previous Review | Audit Status | Code / Architecture Finding |
|---|---|---|
| **1. Official Priority uniqueness may be global instead of batch-specific** | **CONFIRMED & FIXED** | Index was `uq_admissions_official_priority` on `(official_priority)`. Migrated to `uq_admissions_batch_official_priority` on `(academic_year_code, official_priority)` and updated `student_profiles` cohort priority index to include `admission_batch_year`. Verified by new regression tests. |
| **2. Priority recalculation uses chronological fee payment with USN tie-breaker** | **CONFIRMED** | Implemented exactly as specified in `src/student/registry.ts#L265-L270`: `ORDER BY fee_payment_timestamp ASC, college_id ASC`. Preserves staff fee verification requirement. |
| **3. Roommate groups identify students through bare priority numbers** | **PARTIALLY CONFIRMED & HARDENED** | `createRoommateGroup` in `src/preferences/service.ts` accepted `peerPriorityNumbers: number[]`. When resolving, it now looks up students within the active cycle's cohort, and all memberships store `student_id` (foreign key to `student_profiles.id`), ensuring stable relational references. |
| **4. Tests primarily use `pg-mem` rather than real PostgreSQL** | **CONFIRMED** | `src/db/index.ts#L143-L147` defaults to `pg-mem` when `process.env.NODE_ENV === 'test'` or `DATABASE_URL` is unset. Docker/PostgreSQL is configured in `docker-compose.yml` but was not running locally during testing. `pg-mem` correctly evaluates composite unique constraints and transactions. |
| **5. Authentication documentation describes SSO/OTP without working delivery** | **CONFIRMED** | `PortalSelectionView.tsx` and `AuthContext.tsx` support direct ID + Password credentials with student/staff personas. No SMTP, Twilio, or institutional SAML SSO provider is plugged in. |
| **6. Notifications use outbox without external delivery** | **CONFIRMED** | In-app notifications in `notifications` table are fully functional and recipient-isolated. `outbox_events` table receives event records (e.g. `ALLOCATION_CONFIRMED`), but no external daemon is polling/sending them via email or WhatsApp. |
| **7. Live floor map uses in-process fanout, not multi-instance sync** | **CONFIRMED** | Updates are polled at 3000ms intervals by the client via HTTP. No Redis pub/sub or WebSocket cluster bus exists. Adequate for single-instance monolith, requires Redis for multi-pod Kubernetes deployment. |
| **8. Waitlisted students lack automatic promotion workflow** | **CONFIRMED** | Students can be marked `WAITLISTED` (e.g., when displaced by admin override in `src/allocation/engine.ts#L502`), but seat cancellations do not automatically dequeue the next waitlisted student. |
| **9. Quota categories in synthetic data without affecting allocation** | **DISPROVED** | Quotas (`GENERAL`, `MERIT`, `SPORTS`, `PWD`) directly determine the `allocation_pools` record a student joins (`src/allocation/engine.ts#L128-L135`), which partitions seat inventories and turns. |
| **10. Synthetic datasets use inconsistent identity conventions** | **CONFIRMED (INTENTIONAL)** | Pilot tests use `DEMO-001` through `DEMO-030` (`tests/bvb_pilot.test.ts`), while virtual dataset generator creates canonical institutional USNs `1si25<branch><code-3>` (`scripts/generateVirtualData.ts`). Both formats are supported by `AuthContext.tsx`. |
| **11. Documentation phase numbering inconsistency** | **CONFIRMED** | `docs/plan.md` has Phase 0–24, while `docs/implementation-status.md` references Phases A–H and 1–21. Synchronized in status documentation. |
| **12. Unmerged branch changes** | **DISPROVED** | `origin/main` was checked out, fetched, and verified. Pull request #5 was already merged into `origin/main` (commit `133912e`). |

## 4. Public Repository Security Audit

- **Live Credential Exposure:** Tracked files inspected. `.env` is properly ignored in `.gitignore`. No production credentials, live private tokens, or real student PII exist in the repository.
- **Authorization Enforcement:** Server-side `can(actor, action, resource)` checks are enforced across all mutations. Students cannot mutate priority, override allocations, verify fees, or upload mess menus.
- **IDOR Protection:** Notification queries (`src/notifications/service.ts`) filter by `user_id = $1 OR target_audience IN ('ALL', 'STUDENTS')`. Roommate responses verify `student_profile_id` against the authenticated session.
- **Client Bundle Safety:** No private environment variables or server keys are exposed to the client bundle (`dist/client`).
